# hopfield-analysis

Presentation layer of the project: a Python package that reads the files written by the compute layer (`src/compute`) and visualizes them.

## Requirements

[uv](https://docs.astral.sh/uv/). It installs Python 3.13 (`.python-version`) and the locked dependencies (`uv.lock`).

## Setup

Run all commands in `src/analysis`.

```bash
uv sync
```

## Figures

Figures follow the style of the report (`hopfield_analysis.style`): Latin Modern Roman, the font of the LaTeX report, Polish labels and a decimal comma. The font files are bundled in `src/hopfield_analysis/fonts/` under the GUST Font License (`GUST-FONT-LICENSE.txt`), so no LaTeX installation is needed. `--out` takes a path without extension and writes the figure twice: `<out>.pdf` and `<out>.png` (300 dpi).

Figures of an experiment go to `data/experiments/<NN-name>/plots/` (ignored by git, regenerated by the commands) or, if the report uses them, to `data/experiments/<NN-name>/figures/` (committed).

Bitmaps show `1` black and `-1` white, as the previews of `compute convert-images`. The PDF embeds every bitmap, heat map and weight matrix at its full resolution, with every pixel of a small one repeated so it has about 300 dpi at its printed size (PDF viewers smooth an enlarged image and would blur its pixels); the PNG shrinks a large one by smoothing rather than by dropping rows and columns.

## Usage

A recall run (the output directory of `compute recall`):

```bash
uv run hopfield-analysis frames <run> --out <out> [--max 8 | --frames 0,2,5]
uv run hopfield-analysis run <run> --out <out>
uv run hopfield-analysis animate <run> --out <file.gif> [--scale N] [--duration 300] [--hold 1500] [--max-frames 200]
uv run hopfield-analysis view <run>
```

- `frames`: the frames as bitmaps in a grid, each with its number and energy; all frames if there are at most `--max`, otherwise `--max` evenly spaced ones including the first and the last, or the frames listed in `--frames`.
- `run`: energy and overlaps with every pattern against the frame; the target (or the pattern nearest to the final state) in color, the other patterns gray.
- `animate`: a looping GIF of the bitmaps, enlarged `--scale` times (by default the largest integer scale that keeps the longer side at most 256 pixels, but at least 1, so a 300 x 200 bitmap stays 300 x 200), each frame shown `--duration` ms and the last one `--hold` ms. Identical consecutive frames are merged into one with the sum of their times.
- `view`: a window with the current frame, the energy and overlap plots with a marker at the frame and a slider; the arrow keys move by one frame, `Home` and `End` jump to the first and the last one (in this window these keys do not control the toolbar zoom history).

A dataset and a `compute train` run:

```bash
uv run hopfield-analysis patterns <dataset> --out <out> [--registry <datasets.toml>] [--columns 6]
uv run hopfield-analysis weights <train run> --out <out>
```

- `patterns`: the patterns of a registered dataset as bitmaps; the registry is `data/datasets/datasets.toml` found from the current directory upwards unless `--registry` is given.
- `weights`: the weight matrix as a heat map with a symmetric color scale; only for dense weights (`weights.npy`).

An experiment (the results directory of `compute experiment`):

```bash
uv run hopfield-analysis recovery ../../data/experiments/00-example/results --out ../../data/experiments/00-example/plots/recovery
uv run hopfield-analysis classes ../../data/experiments/00-example/results --out ../../data/experiments/00-example/plots/classes
uv run hopfield-analysis recovery ../../data/experiments/08-large-recovery/results --metric nearest-target --out ../../data/experiments/08-large-recovery/plots/nearest
```

- `recovery`: the fraction of recovered runs (`--metric recovered`, the default) or of runs whose final state is nearest their target (`--metric nearest-target`) against the damage level, one panel per dataset (at most three in a row), one line per learning rule and update mode, with the 95% Wilson intervals from `summary.json`. The axis names the damage of the experiment's inputs from `metadata.json`: flipped pixels (`source = "pattern"`) or covered rows (`source = "occlusion"`).
- `load`: the same fractions against the number of patterns `p` of the prefixes of a dataset (`{ name, patterns }` entries of `datasets`, and the whole dataset if listed), one row of panels per dataset in the registry and one column per learning rule, one line per damage level (`--levels 0,0.2`, all by default) of one update mode (`--mode`, `synchronous` by default).
- `classes`: the fractions of the final state classes (pattern, negation, spurious state, cycle, step limit) as stacked bars per damage level, one row of panels per dataset and one column per learning rule and update mode; with more than six damage levels only every k-th bar is labelled.

Stability of the stored patterns of an experiment (`unstable` and `fields` need `stability_fields = true`, which writes `stability.parquet`):

```bash
uv run hopfield-analysis stable <results> [<results> ...] --out <out>
uv run hopfield-analysis fields <results> --out <out> [--datasets a,b] [--log]
uv run hopfield-analysis unstable <results> --dataset <name> --learning <rule> --out <out> [--registry <datasets.toml>] [--columns 6]
uv run hopfield-analysis overlaps <results> --out <out> [--datasets a,b]
```

- `stable`: the fraction of stable stored patterns as bars, one group per dataset and one bar per learning rule, each labelled `stable/p`; the trainings of several experiments are shown together.
- `fields`: histograms of the aligned fields $\xi_i^\mu h_i$, one panel per dataset (at most four in a row), one line per learning rule, a dashed line at zero; `--log` makes the count axis logarithmic, so the narrow peak of one rule does not flatten the others.
- `unstable`: the stored patterns of one dataset with the neurons that one update would change in red and their number below each pattern, for the rule named as in the results (`hebb`, `oja (subspace)`, `oja (single-neuron)`); a neuron is unstable when its aligned field is negative, or zero at a `-1` neuron with `zero_field = "plus-one"`. The patterns come from the registry, as for `patterns`.
- `overlaps`: the overlap matrices $m^{\mu\nu}$ from `datasets.json` as heat maps on the scale $[-1, 1]$, with the values written into matrices of at most eight patterns.

Random inputs (`source = "random"`; `attractors`, `accessibility` and `distinct` need `attractors = true`, which writes `attractors.parquet`):

```bash
uv run hopfield-analysis outcomes <results> --out <out>
uv run hopfield-analysis attractors <results> --dataset <label> --out <out> [--top 6]
uv run hopfield-analysis accessibility <results> --out <out> [--datasets a,b] [--mode asynchronous]
uv run hopfield-analysis distinct <results> --out <out>
uv run hopfield-analysis energies <results> --out <out> [--datasets a,b] [--mode asynchronous]
```

- `outcomes`: the fractions of the final state classes as stacked bars, one bar per dataset, one row of panels per update mode and one column per learning rule.
- `attractors`: the `--top` most frequent final states of one dataset (label as in the results, e.g. `large-25x25` or `letters-14x20:5`) as bitmaps, one row per learning rule and update mode, each titled with the fraction of runs (`< 0,001` for a rarer state) and a description: `wzorzec 2` or `negacja 2` for a stored pattern or its negation, `mieszanina 3` for a spurious state equal to a mixture of three patterns, otherwise the class.
- `accessibility`: the fraction of runs that ended in every stored pattern and in its negation, two bars per pattern, one row of panels per dataset and one column per learning rule, for one update mode.
- `distinct`: for the prefixes of a dataset, the number of distinct spurious fixed points reached (symmetric logarithmic axis) and the fraction of runs that ended in one (with the 95% Wilson intervals) against the number of patterns `p`, one line per learning rule and update mode.
- `energies`: histograms of the final energy from `trials.parquet`, one per group of classes (a pattern or its negation, which have the same energy; spurious state; cycle; step limit), one row of panels per dataset and one column per learning rule, for one update mode.

A capacity run (the results directory of `compute capacity`):

```bash
uv run hopfield-analysis capacity <results> --out <out>
```

- `capacity`: one column of panels per number of neurons $N$; above the mean fraction of stable patterns of a set, below the mean fraction of unstable neurons, against the load $p/N$. One line per source and learning rule, the prediction for random Hebbian sets from `summary.json` as a black dashed line and vertical lines at $p/N = 0.138$ and $1/(2 \ln N)$.

A missing or invalid input ends with a one-line error message and exit code 1.

The module `hopfield_analysis.experiments` reads the results of an experiment: `load_trials` (`trials.parquet` as a polars DataFrame, one row per run), `load_summary` (the cells of `summary.json` as a flat DataFrame, nested fields joined with `_`, e.g. `recovered_fraction` or `nearest_target_fraction`) and `load_metadata`, with `damage` (the kind of damage of the inputs, from the metadata) and `dataset_sizes` (label, registry name and `p` of every dataset). `hopfield_analysis.stability` reads `stability.parquet` (`load_fields`), `datasets.json` (`load_datasets`) and the stability of every training from `metadata.json` (`load_stability`); `hopfield_analysis.attractors` reads `attractors.parquet` (`load_attractors`, one row per cell and distinct final state) with `bitmap_shapes` (bitmap size of every dataset, from the metadata), `accessibility` (fraction of runs that ended in every pattern and negation) and `spurious_counts` (distinct spurious fixed points of every cell); `hopfield_analysis.capacity` reads `capacity.parquet` (`load_capacity`) and `summary.json` of a capacity run (`load_capacity_summary`). `hopfield_analysis.recall.Recall.load` reads a recall run, `hopfield_analysis.datasets.Registry` the dataset registry and `hopfield_analysis.weights.load_weights` the weights of a train run.
